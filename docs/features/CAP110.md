# Optional 110-cap expansion

Port-only, not native. The default stays v1.150 with cap 90, and every switch below is off by default. The expansion
adds later-client content on top of the native tables, joined by codename. Native rows, IDs and names never change.

## Switches

The switches do not imply one another. A build switch changes the published data, so the build and the server must
agree.

| Switch | Where | Effect |
| --- | --- | --- |
| `SRO_ALEXANDRIA` | Build and server | The Alexandria city variant, which the other imports build on |
| `SRO_LEVEL_CAP=110` | Server | Raises the stopping level. Unset, `off`, `false`, `0` or `90` keeps 90; other values fail startup |
| `SRO_CAP110_ITEMS` | Build | Equipment for degrees 10 and 11 |
| `SRO_CAP110_SKILLS` | Build | Skill ranks up to mastery 100 from the later client |
| `SRO_CAP110_SKILL_DATABASE` | Build | Path of a skill export that adds mastery 101-110 |
| `SRO_CAP110_MONSTERS` | Build and server | Field monsters, nests, monster skills, loot tables and rewards |
| `SRO_CAP110_MONSTER_DATABASE` | Build | Directory of the monster export |
| `SRO_CAP110_LEVEL100` | Server | Admits the level 100 monster slice separately from levels 101-110 |
| `SRO_CAP110_SET_BONUSES` | Server | Applies degree 10 and 11 set bonuses |
| `SRO_CAP110_QINSHI` | Build and server | Qin-Shi tomb upper floors, `cap110-qinshi.txt`. Needs `SRO_CAP110_MONSTERS` |
| `SRO_CAP110_TEMPLE` | Build | Temple family, `cap110-temple.txt`. The build writes it; the server has no switch or loader for it, so it does not ship |
| `SRO_PHARAOH_TOMB` | Build and server | Pharaoh Tomb 1-3. Needs `SRO_CAP110_MONSTERS` |
| `SRO_PHARAOH_TOMB_GEAR_RATE` | Server | Multiplies tomb elite and unique equipment rolls, 2 to 20. Unset or 1 is unchanged |

For learnable high ranks, `SRO_CAP110_SKILLS`, `SRO_CAP110_SKILL_DATABASE` and `SRO_LEVEL_CAP=110` must all be set.
With the database tier published and the cap at 90, the ranks show on the board but cannot be learned, and the
gameworld warns once at startup.

Rebuild the level catalogue with the same cap as the deployment. Lowering the cap stops further level gains; it does
not lower characters, remove items or undo rewards. A rollback of a live shard needs its own content and state policy.

## Building

`scripts/build_alexandria_variant.py` runs the importers in order and writes into the optional variant root. The native
extraction is never the output. Turning a flag off removes the shard that flag owns and restores the native manifest.
Edited or unmarked shards are refused, not overwritten.

Published IDs stay stable through markers in the variant root, such as `extracted/.opensro-cap110-monsters.json`. Keep
these markers across rebuilds. Losing the database input on a later build fails, so learned skills cannot silently
disappear.

Compare the two clients, without extracting anything:

```text
python -B scripts/analysis/compare_cap110.py --native-root <native-client> --vsro-root <later-client>
python -B scripts/analysis/skill110_scope.py --native-root <native-client> --vsro-root <later-client>
```

The results go to `.state/cap110-comparison.json` and `.state/skill110-scope.json`.

After every import and server export, run `scripts/analysis/check_identity_parity.py`. It joins the client's and
server's character, skill and item tables by codename, and fails on a differing ID or a one-sided codename.

`cap110_monsters.py` refuses an export that does not match its pinned backup hash (`require_pinned_export`). The import
marker keeps the hash of each exported file.

## Equipment

`scripts/cap110_item_import.py` adds 824 items: 112 weapons, 16 shields, 648 armor pieces and 48 accessories, in
ordinary and Seal grades at degrees 10 and 11. Weapons keep the first ID range. Requirements, statistics, sex and race
stay as authored. Linked codenames must resolve inside native plus imported rows.

- Set gear, 376 rows, imports beside its group catalogue. Set bonuses apply only with `SRO_CAP110_SET_BONUSES` on.
- Links to degree 12 items are trimmed and recorded, because the degree 12 conversion is out of scope.
- Missing descriptions stay absent. Every name is required.
- Circlets and accessories without a worn mesh keep their icon and drop model.
- New particle effects live only in the variant overlay. Later sound modifiers and unsupported particle selectors fail
  the import.

`scripts/alexandria_shop_d10.py` stocks Alexandria's own shops. `STORE_SD_SMITH` and `STORE_SD_ARMOR` are copied from
Khotan's stores, which stay unchanged, and `STORE_SD_ACCESSORY` is restocked in place. Each degree 9 ordinary good gains
the degree 10 good of its family. A tab never exceeds the 45 slots of the largest native tab; the lowest degrees drop
first. Prices come from the item's price column, an inference because v1.150 has no degree 10 shop. Degree 11, grades B
and C, and rare or Seal items are not stocked.

GM spawn: `/MAKEITEM ITEM_CH_SHIELD_10_A 1`. Rare variants append `_RARE`.

## Skills

`scripts/cap110_skills.py` and `scripts/cap110_skill_import.py` add 757 ranks through mastery 100, 555 trainable and 202
chain rows. `scripts/cap110_skill_database.py` adds 761 more for mastery 101-110 from an explicit `_RefSkill` export.
That makes 1,518 rows, with IDs from 31925 to 33442 and no new mastery.

- Groups, chains and prerequisites are remapped by codename. A later group that no shared rank uses gets a fresh ID
  above the native range.
- `scripts/cap110_skill_effects.py` merges the later animation sets native lacks. Native rows win. A later row that
  names an unknown native animation state is refused.
- A mastery is bounded by `MasteryLevelCap` (120) and the character's level.
- The v1.150 client's board never builds a cell for a skill above mastery 90. The browser client does not port that
  gate, so new ranks appear as the mastery reaches them (`skill-slot.ts`).
- About 46 animation bases have no set in either client. They are passive families that are silent in the original too.
- A press audit must not treat passives or the instant imbue path as missing casts. Of the 536 new root candidates, 62
  are passives and 20 use the instant path.

The skill tables differ between clients in numeric IDs, groups and chains, so a converter must remap by stable identity
and never copy the later numbers. The port's skill compiler decodes all imported rows, but decoding is not proof that a
skill behaves correctly in play.

## Alexandria world

- **Field monsters:** 29 types, 1,519 nests and 78 added skills. The importer reserves every published identity before
  allocating new ones.
- **Terrain:** field regions seed the same connectivity walk as the city, bounded by the source availability bitmap,
  so connecting ground and mountains come along.
- **Dimensional gates:** Abundance Ground to Storm and Cloud Desert, and Forbidden Plain to Kings Valley. Both are free,
  need level 95 from Delta, and return free without a level condition. With the monster flag on, gate projection uses
  the 110 ceiling; off, it keeps the level 90 ceiling.
- **Map:** overview textures covering imported regions use the later bytes. City markers and labels project into the
  native table through `scripts/alexandria_map_tables.py`. A new label is admitted only if its text key resolves.
- **Unique presentation:** the imported Apis keeps grade 8. The client grade table has a port-only grade 8 entry for the
  Unique title and icon. No native monster reaches it.

## Pharaoh Tomb

Kings Valley has one gate, `GATE_TOMB_GATE_IN`, linked both ways and free to three exits,
`GATE_TOMB_GATE_OUT_1..3`. The tombs are ordinary outdoor regions, so they reuse the field pipeline: 30 nests each, 17
monster types each, levels 100-110, and five boss families.

These decisions are inferences, not native evidence:

- Each tomb is its own permanent world, registered port-only as `INS_PHARAOH_TOMB_1..3` with IDs 57-59. A variant built
  with the tomb gates only boots with `SRO_PHARAOH_TOMB` on. Off, the catalogue is refused at `names unknown world 57`
  rather than flattening three tombs into the field.
- Bosses are single-spawn nests with their authored respawn delay. The source has no trigger data, so instance
  triggers are not ported.
- The unplaced `GATE_TOMBOSIRIS_*` rows are not carried.

The server side is `monster/pharaoh_tomb.go`, sharing nest validation with `cap110.go`.

## Rewards

`scripts/cap110_rewards.py` imports the items that monster reward rules name and native lacks: 94 alchemy materials and
2 SD tokens, as `itemdata_110001.txt`, with `cap110-rewards.txt` beside it. Group IDs are offset by 1,000,000. The server
reads them in `loot.InitCap110`, which refuses a rule naming a native monster or group. Rewards ride
`SRO_CAP110_MONSTERS`, and the file is required when that flag is on.

Gear odds come only from the level class tables, so tomb gear is rare by design. The website's drop lists describe the
native rule, not `SRO_PHARAOH_TOMB_GEAR_RATE`.

`SRO_ALCHEMY_MATERIAL_DROPS_OFF` discards every type 3/3/11/4 item, assigned drops included. While it is on, the 94
imported materials never drop; only the tokens do.

The SD tokens are in the gold-heap item group, whose body carries a u32 amount where other ETC groups carry a u16 stack
count. `ItemBody` handles this; `TestGoldGroupItemBodyCarriesU32Quantity` pins it.

## Tests against the variant

Native census tests assert native counts. They fail on expanded data by design, for example skill and portal totals.
Verify variant rows separately, and never change a native census to certify a variant.

## Not yet proven

Owner testing covers the CH and EU skill trees, purchases in Alexandria's shops, botting level 101 monsters with drops,
Apis spawning, and travel through all the gates. These remain open:

- A pass from mastery 91 to 110 with one offence, heal, buff and passive per mastery.
- Spawns, combat, boss respawns and drops inside the tombs, and level 102-110 field monsters.
- Tomb monsters at level 100 and non-equipment tomb drops. The equipment catalogue covers levels 101-110.
- SD token pickup, stacking and display.
- A complete visual pass over terrain edges, and the version 13 monster effects the parser accepts with a warning.
- Level-limited consumers such as party matching and the quest guide, which keep era-specific limits.
- A full 90-to-110 playthrough with both flag settings. Keep the expansion off until that passes.
