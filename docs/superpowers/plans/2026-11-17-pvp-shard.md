# Shard PVP Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Um segundo shard `pvp` onde o personagem nasce no nível máximo, com todas as masteries e skills, em Samarkand, e onde NPCs de Samarkand vendem D11 raro +12 e pedras de grau 11 a 1 de ouro.

**Architecture:** Um pacote novo `game/pvpserver` decide se o shard é PVP (`SRO_PVP_SERVER` ligado **e** `SRO_SHARD_ID == "pvp"`) e prepara o personagem na criação, por um hook novo em `agentapi.Config`. As lojas são abas sintetizadas no catálogo de comércio (como `alchemyshop.go` faz para Jangan) presas a três NPCs de Samarkand. A stack Docker ganha um segundo gameworld com volume, rota e env próprios.

**Tech Stack:** Go (apps/server), Docker Compose + nginx (deploy/).

**Spec:** `docs/superpowers/specs/2026-11-17-pvp-shard-design.md`

## Global Constraints

- Port-only, not native: todo código novo leva o comentário "port-only, not native"; a flag desligada deixa tudo idêntico ao de hoje.
- Flag: `SRO_PVP_SERVER` (`on`/`off`, padrão off). Só vale quando `SRO_SHARD_ID` é `pvp`; em outro shard, ignorada com um `log.Warn` no boot.
- Estilo id Software (AGENTS.md): banner de arquivo e de função, constantes nomeadas, gofmt, arquivo < 1000 linhas.
- Testes quebram por comportamento, nunca por texto de fonte.
- Valores do spec: nível = `SRO_LEVEL_CAP` do shard (110 em produção); ouro inicial `100_000_000`; preço das lojas PVP `1`; plus `12`; pedras grau `11`; aba com no máximo `45` itens.
- Samarkand: região `27244`, x `270`, y `180`, z `1421` (chegada do `GATE_CA`, teleportdata.txt).
- Gate local de cada tarefa: `cd apps/server && go test -p 2 ./internal/<pacotes tocados>/...`. Ao final: `pnpm task check:server`.

## Review Focus

1. Personagem europeu: masteries `513-518`, skills só de raça europeia (`RequiredRace`), STR/INT pela mesma fórmula. Teste em Task 2 e Task 3 com um personagem `CHAR_EU_*`.
2. Flag ligada num shard que não é `pvp`: nada muda (criação e loja). Teste em Task 1 e Task 5.
3. Skills de corrente (`ChainSub`) e as que não se aprendem (`SPCost == 0`) ficam de fora; uma skill que exige duas masteries só entra se as duas estiverem no nível. Teste em Task 2.
4. O kit inicial nativo (equipamento de criação, flechas) ainda é aplicado, e o ouro de 100M não é sobrescrito por ele. Teste em Task 4.
5. A projeção da loja para o cliente leva o `+12` do item (o cliente mostra o plus antes da compra). Teste em Task 5.
